## 功能结果

### 配置可靠性

- 主配置通过同目录临时文件写入、文件刷新和原子替换发布。
- 新保存成功前不会把半写内容变成主文件或备份。
- 最近一次成功主配置保留为单一 `.bak`。
- JSON、schema 或任一中继字段损坏时，整份配置失败，不静默过滤条目。
- 只有当前 UUID 文件对应的有效 `.bak` 可用于恢复。
- 恢复前保留 `.corrupt-N`，恢复完成后的当前命令返回
  `CONFIG_RECOVERED_RETRY`，不继续执行保存、删除或点火。

### 玩家快照保存

- `/pearlrelay save <名称>` 从命令玩家采集当前维度、脚部精确坐标和真实
  方块命中点。
- 命中点复用生产目标解析器，保存 schema 仍为 v2。
- 完整参数形式保持兼容。
- 控制台、无方块命中、未加载区块、无效几何和被占用出生点使用稳定原因
  拒绝。
- 保存时允许创建者本人站在采集点；未离开便点火时在生成假人前拒绝。

## 中途失败与修复

### Fabric 单人世界关闭死锁

生产 JAR 20 轮首次运行在完成单人场景后卡住。线程栈显示：

- Render 线程在 `IntegratedServer.halt()` 等待服务端；
- Server 和 Test 线程在 Fabric Client GameTest `Phaser` 等待 Render 线程。

这属于测试框架关闭竞态，不在模组执行路径。最终测试把三个场景统一放入
真实测试专服连接，保留原有行为覆盖并避免 `TestSingleplayerContext.close()`
路径。调整后专服能正常保存世界并退出。

### 重复相同角度未发送

生产 JAR 20 轮第二次运行在第 5 次快照前发现服务端未看到客户端目标命中。
原因是连续重复相同视角时客户端可以不发布新的旋转。最终夹具每轮先通过
真实客户端转离目标并等待服务端确认，再转回目标；失败信息同时记录服务端
位置、yaw、pitch、命中类型、方块和命中点。调整后开发与生产 JAR 均通过
20/20。

## 审查结论

- 正确性：快照采集值、目标指纹、保存后点火和清理都有命令级及真实客户端
  证据。
- 安全性：路径由 UUID 构造；损坏正文不进入玩家消息或日志；拒绝路径不
  生成假人、不交互、不加载目标区块。
- 兼容性：旧 schema v1、当前 schema v2 和完整参数保存形式均回归通过。
- 可维护性：配置持久化、恢复错误和目标解析保持独立边界；生产 JAR 不包含
  GameTest source set。
- 性能：新增工作只发生在保存命令或配置读写；点火热路径没有新增扫描或
  强制区块加载。

未发现高严重度合入阻塞项。
