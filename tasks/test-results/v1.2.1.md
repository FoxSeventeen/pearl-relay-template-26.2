# Pearl Relay v1.2.1 热修复验证报告

## 当前结论

状态：**本地候选 PASS；GitHub Actions、正式 Release、main 合入和生产部署待完成。**

v1.2.0 在同一玩家配置包含多个旧点时，保存新点或逐个重存旧点会把整份
文件写成 schema v2；下一次读取又因为其他旧点没有目标指纹而把混合文件
判为损坏，并从 `.bak` 回滚。结果是新点从 `list` 消失，而旧点继续返回
`RELAY_REQUIRES_RESAVE`，导致多旧点配置无法逐步升级。

v1.2.1 保持所有结构和字段校验，只允许缺少目标指纹的旧点与完整目标指纹
点在 schema v2 文件中共存。旧点仍不能直接点火，但可以逐个同名重存，不再
阻止其他点保存、列出或使用。

## 测试驱动证据

RED 阶段先增加两个生产形态测试：

1. 两个旧点存在时新增第三个完整点；
2. 两个旧点存在时只升级其中一个。

修复前目标测试共 11 项，其中新增两项均因
`RelayConfigException`/`InvalidConfigException` 失败，并进入和生产一致的
恢复路径。

GREEN 阶段只改变目标指纹校验合同：目标指纹缺失表示待升级旧点；目标指纹
一旦存在仍必须完整有效。新增命令级 GameTest 覆盖：

- 玩家简写保存第三个新点；
- `list` 同时显示两个旧点和新点；
- 同名重存第一个旧点后，第二个旧点和新点仍可列出；
- 未升级旧点继续稳定返回 `RELAY_REQUIRES_RESAVE`；
- 整个流程不产生 `.corrupt-1`。
